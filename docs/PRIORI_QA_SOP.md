# PRIORI 題庫建置與驗收規範

本文件供 Codex、Gemini 與後續接手者共同使用。適用於新年度入庫及既有年度回溯驗收。自動檢查只負責篩出疑點；不可將檔案存在、契約通過或部署成功等同逐題內容正確。

## 上線前後順序

1. 建立原卷來源與版本清單，逐頁確認科目、年級、題號、答案卷及原始音檔；缺少官方答案要標示參考答案。不得假設 115 年有答案卷。
2. 先逐卷拆解大題與作答說明，記錄題號起訖與每題要求：共用文章／題幹、單一題圖、三張圖片選項、原始聽力、文字選項、答案來源。題組說明涵蓋整個題號範圍；不能只搜尋每題 `questionText` 或僅依 `groupId` 判定。
3. 使用既有 Chrome PDF 渲染管線處理原卷，逐題裁圖。保留題意、標號和指示箭頭；不得截入相鄰題、下一組說明、解答或裁掉選項。原始音檔依題切割，逐段確認題號、內容、起訖、重播次數與音量。每項自動比對均須有來源紀錄。
4. 入庫時核對每題題幹、所有選項、正解、題圖、題組、音檔與解說；朗讀要忠於題目，不讀出正解或提供額外提示。出題用圖、可放大的圖與可印出的圖都要核對，勿只核對原卷模式圖片。
5. 對全部題目執行結構、資產存在、音圖規格與程式可辨識疑點篩查。將結果標為「待原卷核對」，禁止把 0 警示解讀為通過；要記下未能自動判定的範圍。
6. 上線前按每科每卷的大題／題型各抽 1–2 題實際操作：共用題組各抽邊界題、看圖題與圖片選項題、第一／末一段音檔、文字及分數、幾何、朗讀、放大、正誤判分與 A4/A3 列印。用隔離環境或訪客，勿寫入真實學生紀錄。對每類中風險較高或可疑者加抽；發現系統性問題須擴大到同類全部題目。
7. 內容問題、可能誤判分數或漏圖漏音修復後，對照原卷重驗該題及同類題，執行適用契約、lint、build、PRIORI E2E、全站 smoke；只有應完成的內容、技術門檻均通過才能核可新卷上線。未核完即發布必須明確標示待驗收，不得宣稱通過。
8. 上線後檢查正式站版號、CI／部署、資產 Content-Type、代表性連結與訪客作答；另請老師使用實體 iPad／Safari、觸控、聲音與學校印表機完成抽樣。瀏覽器視窗模擬不是實機驗收。

## 記錄與交接

每題至少保留年度、科目、年級、題號、原卷頁碼／大題、共用範圍、圖音必要性、題庫資產、正解來源、朗讀／放大／判分／列印抽測、狀態（待驗、已核、疑點、已修復待複驗）、證據與日期。可使用 `scripts/screen_priori_content.mjs` 產生第一版檔案清單；另補原卷目視清單，不要用產生清單覆蓋既有人工記錄。

每輪保存問題、影響、修復提交、驗證方法及未完成範圍，並在 `HANDOVER.md` 留下入口。答案卷若位於公開靜態目錄，即使介面僅顯示教師入口，知道網址者仍可下載；以既有教學風險邊界如實說明。

PowerShell 範例（輸出放在專案外，勿覆蓋人工紀錄）：

```powershell
node scripts/screen_priori_content.mjs (Get-Location).Path 'C:/Users/user/Documents/chatgpt/priori-audit/output'
```
